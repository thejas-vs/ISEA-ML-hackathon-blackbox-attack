# Black‑Box Decision‑Based Adversarial Attack

**Repository:** `blackbox-attack`

---

## Problem Statement
We target a pretrained image classification model (loaded from `models/cnn_model.pt`) with **only label‑only (decision‑based) queries**.  The goal is to generate adversarial images that are visually indistinguishable from the original clean images yet cause the model to output a different class label.  The dataset consists of **1000 PNG images** located in `data/clean/`.

- **No access to model internals** – only `BlackBoxModel.predict_label` is allowed.

## Method Overview
The attack follows the **HopSkipJumpAttack (HSJA)** style, implemented from scratch with NumPy:
1. **Initialization** – generate a random‑noise image (or blend with a random image) that is already mis‑classified.
2. **Binary search to the decision boundary** – shrink the line segment between the clean image and the adversarial point until we land just on the boundary (configurable tolerance).
3. **Gradient‑direction estimation** – sample many random directions on the unit sphere, query the model for their labels, and compute a Monte‑Carlo estimate of the gradient sign.
4. **Geometric step** – move a step opposite to the estimated gradient; if the step crosses back to the clean side we halve the step size and retry, then binary‑search again toward the clean image.
5. **Iterate** – repeat steps 3‑4 for a configurable number of iterations or until the per‑image query budget is exhausted. Monte‑Carlo sample count grows with the iteration number (as in the original HSJA paper).
6. **Safety‑check** – after the loop, the resulting image is rounded to `uint8` and clipped to `[0, 255]`. If the rounding flips the label back, we move a tiny additional distance away from the clean image until the label stays adversarial.
7. **Optional refinement** – a post‑processing stage (`code/refine.py`) shrinks the perturbation, sparsifies small values, and optionally low‑pass filters it, all using only label queries.

1. **Environment** – Python 3.11 with the following packages (already present in the workspace):
   ```
   numpy, scipy, scikit-image, pillow, matplotlib, torch, torchvision
   ```
2. **Run the notebook** (self‑contained):
   ```bash
   jupyter notebook code/p2_code.ipynb
   ```
   Execute all cells – the notebook loads a small subset (3 images) and demonstrates the full pipeline.
3. **Run the full attack** (with resume support):
   ```bash
   python code/run_all.py --start 0 --end 1000
   ```
   - The script writes each adversarial PNG to `outputs/adversarial/` and logs results to `outputs/results.csv`.
   - To resume after interruption, simply invoke the script with the desired `--start` and `--end` range; already‑processed images are skipped.
4. **Validate the outputs** (optional):
   ```bash
   python code/validate_outputs.py
   ```
   This re‑loads every PNG, checks the label flip, computes final aggregate metrics, and writes `outputs/final_summary.json`.

## Limitations & Honest Notes
- **Query budget** – The attack requires ~3 k label queries per image (≈3 M total).  On slower hardware this can become a bottleneck.
- **Determinism** – Results are reproducible only when the same random seed is used; different seeds may lead to slightly different perturbation magnitudes.
- **Refinement cost** – The optional refinement step adds extra queries (≈10 % of the budget) and only yields modest L₂ improvements on many images; it can be disabled if query efficiency is paramount.
- **Model‑specific behaviour** – Success and perturbation size are tied to the particular CNN model provided; a harder model may need a larger budget or more iterations.
- **No guarantee of perceptual invisibility** – While PSNR/SSIM are high, the attack is still perceptible under strong magnification (as shown in the example figures).
